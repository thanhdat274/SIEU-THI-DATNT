# ROLE
You are a Principal Game Engineer, Game Designer, Full-stack Architect, and Technical Lead specializing in scalable browser-based 2D simulation games.

Your task is to design and implement a production-oriented Vietnamese grocery store simulation game named "Tiệm Tạp Hóa Đầu Hẻm".

This is a real playable game, NOT a static UI demo, landing page, or isolated prototype.

The game must run on desktop and mobile browsers, support offline gameplay, cloud saves, Google authentication, and future multiplayer expansion.

## 1. MANDATORY TECH STACK

Frontend:
- React + TypeScript + Vite
- PixiJS v8 for 2D rendering
- ECS architecture using bitecs or a justified equivalent
- Zustand for UI state
- Tailwind CSS for responsive UI
- Tiled-compatible JSON maps
- IndexedDB via Dexie
- PWA support

Backend:
- NestJS + TypeScript
- MongoDB Atlas with Mongoose
- Firebase Admin SDK for ID token verification
- REST API with versioning and DTO validation

Authentication:
- Firebase Authentication
- Google Sign-In
- Firebase UID as external identity
- Never expose MongoDB credentials or Firebase Admin credentials in the browser

Deployment:
- Vercel for frontend
- Independently hosted NestJS API
- MongoDB Atlas for persistent data
- Static assets on CDN/Vercel

Use a monorepo structure with pnpm workspaces.

Do not replace these technologies without explaining a technical blocker.

## 2. GAME CONCEPT

Genre: Cozy 2D Grocery Store Management + Life Simulation + Tycoon.

Setting: A small Vietnamese neighborhood.

The player inherits a tiny grocery store and gradually develops it into a larger business.

Progression:
1. Run a small grocery store manually.
2. Purchase and sell everyday goods.
3. Expand shelves and product categories.
4. Unlock neighboring land.
5. Build a warehouse.
6. Hire employees.
7. Automate store operations.
8. Open food and beverage counters.
9. Manage multiple departments.
10. Eventually operate multiple branches.

The game should feel alive, cozy, culturally Vietnamese, and rewarding without excessive repetitive clicking.

## 3. CORE GAMEPLAY

Implement a complete gameplay loop:

Open store -> Restock shelves -> Customers arrive -> Customers browse -> Checkout -> Earn money and XP -> Manage inventory -> Close store -> Review financial report -> Upgrade store.

The game must include:
- Playable character.
- Customer NPCs.
- Grid-based map.
- Shelves and product placement.
- Inventory.
- Purchasing from suppliers.
- Checkout.
- Currency.
- Experience and leveling.
- Unlock progression.
- Daily tasks.
- Local save and cloud save.

All major features must be interconnected.

For example:
Purchasing goods increases warehouse inventory.
Restocking transfers goods from warehouse to shelf.
Customers purchase from shelf stock.
Checkout decreases stock and increases money.
Sales contribute to quests, XP, and financial reports.

## 4. GAME WORLD

Use a 2D top-down or 2.5D pixel-art visual style.

The starting store has an 8x8 tile layout.

Support:
- Tile-based maps.
- Camera movement and zoom.
- Collision.
- Interactive objects.
- Layered rendering.
- Character animations.
- Building mode.
- Expandable land.
- Indoor and outdoor areas.

Implement a map loader compatible with Tiled JSON.

The map system must support future map expansion without rewriting the renderer.

## 11. SAVE SYSTEM

Use IndexedDB as the primary local save layer.

Use MongoDB as the cloud persistence layer.

Save:
- Player profile.
- Level and XP.
- Currency.
- Shop layout.
- Land expansion.
- Inventory.
- Employees.
- Quest progress.
- Current game day.
- Statistics.

Implement:
- Save schema versioning.
- Revision numbers.
- Local autosave.
- Cloud synchronization.
- Conflict detection.
- Migration support.
- Recovery from interrupted saves.
- Export/import save files.

Do not save NPC movement every frame.

Cloud synchronization should use compact snapshots and important checkpoints.

Do not overwrite a newer save with a stale save.

## 12. FIREBASE AUTHENTICATION

Implement Google Sign-In using Firebase Authentication.

Frontend:
- Sign in.
- Sign out.
- Authentication state.
- Firebase ID token retrieval.

Backend:
- Verify ID token using Firebase Admin SDK.
- Extract verified UID.
- Find or create player.
- Enforce ownership checks.
- Reject unauthorized requests.

Never trust a client-provided UID without token verification.
